# UX-002 Meals Basket — 2026-10-02

Scope: categorized dish browsing on Meals and a single-submit order basket ([proposal §2](../proposals/2026-10-01-ui-expansion.md), [ADR 0008](../decisions/0008-order-basket.md)). Branch `claude/ux-002-basket`, based on `main` at `532292d`. This is a web-only change: no API, database migration or new dependency.

## Acceptance evidence

| Criterion                                                    | Evidence                                                                                                                                                                                            |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Meals opens a categorized, searchable dish list with Add     | `basket.spec.ts`: Meals opens on "Order dishes"; dishes grouped under their category and Uncategorised; search and category filters change only the list                                            |
| Repeated adds increase servings; visible basket summary      | First Add uses base servings, "+" adds one, "−" removes one and at zero removes the dish; the summary shows dishes, servings and points (for example "3 dishes · 7 servings · 16 pts")              |
| Session basket, isolated by household, no server order early | Basket survives page change, language switch and reload; the orders API still returns 0 orders before Place order; one storage key per household (isolation reasoned from code, not browser-tested) |
| Review items, servings, notes and timing; one Place order    | Review shows each dish's servings and remove control, notes and now/later timing; "Add more dishes" keeps edits; placing creates exactly 1 order with both dishes, 11 pts and the notes             |
| Closing or emptying the basket creates no order              | Emptying (confirmed) and removing every dish leave 0 orders; Place order is disabled when empty; a reload after placing does not resubmit                                                           |
| Stale edit conflict; members edit each other's orders        | Existing `orders.spec.ts` conflict case passes with the basket flow; integration AC-03/AC-04 order tests unchanged and passing                                                                      |
| Archived dish                                                | A dish archived after it was added is removed from the basket on load, with a notice                                                                                                                |
| Keyboard, locales, accessibility                             | Keyboard-only flow adds to the basket, steps servings and places the order at 360 px; Chinese summary text; axe scans of the dish browser with basket and of the review form report 0 violations    |

## Checks run

On the owner's Mac with Node 24.19.0 and the loopback `family_menu_test` database:

- Full `npm run check`: format, lint, typechecks, production builds, 75/75 integration tests and 72/72 desktop/mobile browser cases passed.
- The first full run failed 2 cases in `states.spec.ts`. That test mocked an orders failure, but Meals now opens on the dish browser, which does not fetch orders. The test now opens Upcoming before asserting the server-error message, and the full rerun passed.
- The agent reviewed mobile screenshots of the dish browser with the basket bar and of the review form.

## Not verified

- Real-phone review by the owner, including the sticky basket bar at 200% zoom.
